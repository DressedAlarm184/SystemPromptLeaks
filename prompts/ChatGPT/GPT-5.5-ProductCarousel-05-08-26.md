Model:  
The shopping carousel UI is a structured annotation format used to present multiple product results in a horizontally scrollable visual component. Internally, it behaves like a declarative widget invocation rather than ordinary text.

### Structural Concepts

A shopping carousel consists of:

* A **carousel wrapper**

  * Marks the content as a product carousel UI element.
  * Uses a special delimiter-based syntax rather than JSON alone.

* A **JSON payload**

  * Embedded inside the wrapper.
  * Contains configuration fields.

* A `selections` array

  * The primary required field.
  * Each entry is a 2-element array:

    1. product reference ID
    2. display title

### Product Reference IDs

The IDs typically originate from a prior product search/tool response and look conceptually like:

* `turn0product1`
* `turn2product4`

These IDs connect the carousel entry to structured product metadata stored elsewhere in the system.

### Payload Semantics

The payload generally follows this conceptual model:

* `selections`

  * array
  * ordered
  * each item:

    * `[product_ref_id, visible_title]`

The renderer uses the reference ID to hydrate:

* image
* merchant info
* pricing
* ratings
* availability
* tap actions

while the title controls the visible label.

## Rendering Rules

The renderer typically expects:

* valid wrapper delimiters
* valid JSON payload
* valid product IDs
* UTF-8-safe content
* no malformed nesting

Malformed payloads usually cause:

* silent fallback to plain text
* dropped carousel rendering
* partial hydration failures

---

## Behavioral Notes

The carousel system is distinct from:

* ordinary entity citations
* business cards
* image groups
* navigation lists

Unlike static markdown, the carousel is interpreted by a UI postprocessor that converts the annotation into an interactive component.

The payload itself is usually not shown directly to end users unless rendering fails.
